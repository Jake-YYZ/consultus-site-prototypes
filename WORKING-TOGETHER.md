# Working Together on the Website Project

How Jake and Shannon share this project without stepping on each other.
None of this is complicated. Claude Code handles the technical parts. These are
just the habits that keep us in sync.

---

## The golden rule

**Pull before you start. Push when you finish.**

- **Before you begin a work session,** tell Claude Code:
  *"Pull the latest from GitHub first."*
  This grabs whatever the other person changed so you're always building on the
  newest version of the site.

- **When you're done for the session,** tell Claude Code:
  *"Push my changes."*
  This sends your work up. It goes live automatically about a minute later.

If you remember nothing else, remember those two lines.

---

## Split the work so we're never in the same page at once

The one thing that causes a mess is **both of us editing the same page at the same time.**
Easy to avoid: we divide up the pages.

- Before starting something new, give the other person a quick heads up on what you're
  taking (a Slack message or text is plenty).
- Stick to your own pages for a session rather than hopping into one the other person
  is actively working on.

We'll agree on a rough split (for example, one of us on case study pages, the other on
city pages). It doesn't have to be rigid, just clear enough that we're not colliding.

---

## If you ever see a "conflict" message

Now and then, if we both touched the same file, Claude Code will say there's a
**conflict.** Don't panic and don't force anything. Just tell Claude Code:

*"Help me resolve this conflict."*

It will walk you through keeping both sets of changes. It looks scarier than it is.
If you're unsure, message the other person before resolving so we don't accidentally
undo each other's work.

---

## How changes go live

- The moment you **push**, the site rebuilds and updates automatically.
- Give it about **one minute**, then it's live at:
  **https://jake-yyz.github.io/consultus-site-prototypes/**
- There's no separate "publish" button. Pushing is publishing.

Because pushing goes live right away, **preview your work locally first** (Claude Code
can show you the page in your browser before you push) so we're only pushing things we're
happy with.

---

## A few brand rules to protect as you write

These are Consultus Digital house style. Keep them intact on every page:

1. **Never use em dashes** in any copy. Use commas, periods, or rewrite the sentence.
2. The brand name in copy is always **"Consultus Digital,"** never just "Consultus."
3. To build a new page that matches the brand, **start from an existing page** rather
   than from scratch. Claude Code knows to do this, just ask it to base a new page on a
   similar existing one. That keeps fonts, colors, header, and footer consistent.

---

## When in doubt, ask first

If something feels irreversible (deleting a page, big structural changes, anything you're
unsure about), **check with the other person before doing it.** A 30-second message saves
a lot of cleanup. Claude Code is also told to confirm before deleting anything, so you've
got a safety net either way.

---

That's the whole playbook. Welcome aboard.
