# Consultus Digital — Design Prototyping Environment

## What this project is

A complete static export of consultusdigital.com (downloaded from Netlify). Jake (President of Consultus Digital, not a developer) uses it to design campaign landing pages, interactive concepts, and page redesigns. Explain technical things in plain English and handle all technical steps for him.

**Production plan (decided July 2026): the site ships as this static HTML, NOT a WordPress rebuild.** Only the blog will live on WordPress. Edits made here are production-bound, not throwaway spec: SEO fixes, redirects, metadata, and content changes in these files are the real thing. Anything that needs a real server (true 301 redirects, per-page lastmod, etc.) must be solved with the static host's tooling (e.g. `_redirects` on Netlify) rather than assumed away.

## How the site is structured

- Every page is a folder containing a single `index.html` (e.g. `about/index.html`, `seo-toronto/index.html`). URLs map 1:1 to folders.
- Each `index.html` links the shared stylesheets in `assets/css/` and keeps only its own page-specific rules in an inline `<style>` block (see **Shared CSS** below). `/assets/css/site.css` is the shared design system (tokens, nav, buttons, sections, cards, footer, service-areas band, FAQ) and is linked by 156 pages; `service.css` by the 18 service pages, `case-study-shell.css` by the 7 case studies built on the Eco Choice shell, `industry-template.css` by the 7 industry pages, `city-page.css` by the 59 city service pages, `division.css` (plus the script `/assets/division.js`) by the rebuilt division pages (`healthcare/`, `home-services-marketing/`). `/assets/fonts.css` holds the font declarations. Pages with their own separate designs (`proposal/`, `roveia-concept/`, `404.html`) still carry all their CSS inline.
- **To create a new page that matches the brand:** copy an existing page (the homepage `index.html` or a service page like `cro/index.html`), keep its `<link rel="stylesheet">` tags (fonts.css plus the shared files that page type uses), nav, and footer, keep or replace the page-specific inline `<style>`, and replace the body sections. This guarantees brand consistency.
- Shared assets live in `assets/`: fonts (`assets/fonts/`), brand mark (`assets/brand/consultus-mark.svg`), hero/team videos (`assets/video/`).
- The logo is an image file, not embedded: `assets/brand/consultus-wordmark-dark.png` (nav) and `consultus-wordmark-light.png` (footer), stored at half size (1036x187) because they display at most 177x32.
- Ignore: `consultus - website inspo - final.backup.html` (old single-file prototype), `zi4edkzp`, `zirh7zqj`, `zivb9k9s` (leftover zip bundles from the Netlify download), `launch-qa-report.txt`, `link_audit.md`, `redirects.csv`, `_redirects`.

## Shared CSS (consolidated Sep 30 2026)

Before this change every page carried ~130 KB of near-identical inline CSS (and two ~110 KB base64 logos). Now:
- The four files in `assets/css/` hold the rules shared by the pages that link them, in the exact cascade order those pages had. A page never gets a rule that could change it: a rule only sits in a shared file if every page that links the file either has it or has no element (and no script-added class) that the rule could match. The two logos are files: `assets/brand/consultus-wordmark-dark.png` (nav) and `-light.png` (footer), stored at half size (1036x187) because they display at most 177x32.
- **Editing a shared file changes every page that links it.** Preview at least one page of each type that links it (regular pages, a service page, a case study, an industry page) after editing.
- **Re-asserted copies.** Where a page-specific rule used to sit before a shared rule it could conflict with (same element, same specificity, overlapping property), the page keeps an inline copy of that shared rule, in its original position, under the comment `/* re-asserted from the shared CSS so this page keeps its original cascade order */`. Those copies come after the `<link>` tags, so a change to the same selector in a shared file does NOT reach those pages. 127 pages have them (400 rules in 242 marked runs, 32 distinct selectors; by far the most common are `.faq-item .faq-a` on 87 pages and `.faq-item:last-child` on 28). Before changing a selector in `assets/css/`, run `grep -rl --include=index.html "re-asserted" .` and look for your selector under that comment. They exist because those pages carry a different variant of a rule than the shared file (for example two generations of the FAQ markup); unifying the variants lets the copies be deleted.
- **Small labels on dark sections are white everywhere** (decision 30 Sep 2026): `.eyebrow.dark`, `.section-lbl.dark`, `.stat-lbl`, `.dark-full .method-num` and `.dark-full .method-desc` are `#FFFFFF` on every page. Before that the 70 city and location pages used white and the other 86 pages used `#C7C5C8`.
- **Commit the CSS with the pages.** `git add -A assets/css` is required; the pages link those files, and a commit of only the modified `index.html` files publishes unstyled pages.
- **City service pages (Oct 6 2026).** The 59 city pages (`cro-agency-in-<city>`, `facebook-advertising-agency-in-<city>`, `the-best-microsoft-advertising-agency-in-<city>`, and Instagram / Google Ads / SEO under `locations/`) link `assets/css/city-page.css` and carry `<body class="cs-page">`; every rule in that file is scoped to `body.cs-page`, so no other page is affected. They were rebuilt from the generic `.sec` / `.accent-card` / `.method-grid` blocks (100px section padding, five 200px process columns, 340px-tall near-empty result cards) into purpose-built `cs-` components: `cs-sec` (80px rhythm, `cs-bone` for the tinted bands), `cs-why` (sticky title beside the copy; the old "In <city>" section is now a `cs-callout` inside it), `cs-rows` / `cs-row` (process steps and services, number + title left, copy right), `cs-stories` / `cs-story` (whole-card link, client logo from the case study it links to), `cs-split` (About and FAQ). Section order: hero, stats band, Why, Method, Services, Success Stories, About, FAQ, CTA, alternating paper and bone. Lists the export had flattened into run-on text (A/B Testing, SEO On-Page, Microsoft intake, remarketing, Google Ads audit and setup; 34 paragraphs) are real lists again (`cs-chips` when every item in the section is short, otherwise `cs-list`). Result card numbers were checked against their case studies before naming the client. The Tampa Facebook team block lost its "Drop team photo" placeholder and the Jake-fronted lines. The pages were generated by a one-off script; edit them directly. Hand-built variants: Facebook Tampa and San Antonio, Google Ads San Antonio and Vancouver. The stats band shows three figures (1,824,639 leads, 4,124,537 calls, 50+ experts): the "1,100 client testimonials" stat was removed from 57 pages on Oct 6 2026 at the user's request, and `city-page.css` lays a 3-stat band out as three columns. **No "free audit" offers anywhere** (decided Oct 6 2026): the 22 audit-teaser sections on the vertical landing pages and Facebook city pages read "Book a Call" with one button, and the two Google Ads city pages that mentioned a free account audit no longer say "free". Don't add "free audit" wording back.
- **Headingless content blocks (Oct 6 2026).** `.content-block` is a 1fr/2fr grid (heading left, copy right). A block with no `<h3>` used to drop its copy into the narrow left column; `.content-block > :only-child` in `site.css` now spans the row at max-width 720px. That fixed 169 blocks on the 56 city service pages and the Tonic Eye Care case study. Give new content blocks an `<h3>`, or rely on this rule.
- **Cache.** There is deliberately no `_headers` cache rule, and the repo's links stay unversioned. **Kinsta caches for 10 years** (checked Oct 8 2026: `Cache-Control: max-age=315360000` on `/assets/css/*.css`, `*.js`, fonts and images; HTML has no cache header), so a changed CSS/JS file at the same URL never reaches a browser that already has it. Fix (Oct 8 2026): `tools/kinsta/deploy_site.py` stamps every CSS/JS link in the uploaded copy with `?v=<hash of the file>`, so editing a stylesheet or script changes its URL on the next deploy. **Always deploy with that tool, never with a hand-typed rsync, or the stamps are lost.** Images, videos and fonts are not stamped: give a replaced file a new name (or extend the tool). Hard-refresh (Cmd+Shift+R) is only needed for pages deployed before Oct 8 2026. New HTML must still look acceptable with OLD CSS; that is why the burger button ships with the `hidden` attribute (old CSS shows nothing, new CSS reveals it on phones).
- **How it was verified.** Every changed page was compared against a pre-change copy at 1440, 1024, 768 and 390 px by hashing the computed style of every element. The only differences are the intended white labels (66 pages have those elements; none of the city or location pages change) and timing noise from the pages' own scripts (carousel images, scroll reveals), which disappears on re-run. Hover, focus, `details[open]` and script-toggled states cannot be seen that way; the cascade-order analysis treats those states as possible, and independent reviewers re-checked them.

## Fonts

One typeface, custom licensed: **NuberNext**. Loaded via `/assets/fonts.css`. Brand rule: "One face. Two voices."

- `NuberNext` Regular (400) + Italic — body text and all display headlines
- `NuberNext` DemiBold (600) + Italic — emphasis, sub-heads
- `NuberNext Wide` DemiBold (600) — H3s and section labels ONLY, never body text

CSS variables (defined in `:root` in `assets/css/site.css`):
- `--sans` and `--serif` both resolve to `'NuberNext', 'Helvetica Neue', Arial, sans-serif` (ignore stale CSS comments mentioning Fraunces/Inter, those refer to an older direction)
- `--wide`: `'NuberNext Wide', ...` for labels
- `--mono`: `ui-monospace, 'SF Mono', Menlo, Consolas, monospace` for eyebrows/labels

⚠️ Path gotcha: `fonts.css` references `NuberNext-Regular.otf` (capitalized) but the files on disk are lowercase (`nubernext-regular.otf`). Works on a Mac (case-insensitive), **will 404 on GitHub Pages** (case-sensitive). Also all asset URLs are absolute (`/assets/...`), which breaks under a GitHub Pages project URL prefix. Fix both when deploying.
